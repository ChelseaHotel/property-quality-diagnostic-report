# 隐私与公开发布规范

## 数据分级

- `local`（默认）：根据用户上传文件生成业务报告，完整保留项目、人员、工单和问题信息。
- `safe`：仅在用户明确要求脱敏或匿名化时启用，匿名化人员和工单，清理自由文本标识符。
- `public`：仅用于 GitHub 或公开演示，只允许合成数据。

Skill 源码、测试夹具、说明文档和仓库历史不得包含真实业务敏感信息。该约束不等于默认脱敏用户生成的本地报告。

## 敏感内容

- 项目、公司和区域名称。
- 工单号、系统编号、问卷编号。
- 姓名、手机号、邮箱、身份证号。
- 房号、楼栋、单元、地址和车位号。
- 提交人、责任人和整改人。
- 问题描述中的现场定位信息。
- 本地绝对路径、用户名、临时目录和截图路径。
- HTML 内嵌 JSON、日志、浏览器截图和 Git 历史。

## 脱敏规则

- 使用带盐 SHA-256 生成稳定匿名编号；从 `QUALITY_REPORT_SALT` 读取盐。
- 未设置盐时使用单次随机盐，并提示匿名编号无法跨报告关联。
- 人员按本报告首次出现顺序映射为“人员-01”等编号。
- 将手机号、邮箱、身份证号、楼栋、单元、房号和车位号替换为类型占位符。
- `public` 模式隐藏真实源文件名和路径，报告标题使用公开示例名称。

## GitHub 防线

公开仓库忽略生产输入与生成物：

```gitignore
outputs/
*.xlsx
*.xls
*.csv
*.pdf
*.png
.env
*.local.json
```

模板 HTML 可以提交，真实报告 HTML 不得提交。提交前运行敏感信息扫描；扫描失败时停止发布，不得使用忽略参数绕过。

README 可提交由 `scripts/make_sample.py` 合成数据生成、并经人工视觉复核的固定公开预览图。允许路径仅限 `assets/readme/` 下扫描器明确登记的文件；替换图片后必须重新核对画面文字，不得使用真实业务截图。
