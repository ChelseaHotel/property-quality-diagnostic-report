# 输入结构与配置

## 标准字段

| 内部字段 | 常见表头 | 要求 |
|---|---|---|
| `id` | 整改单号、工单号、记录编号 | 可选但建议提供 |
| `project` | 项目、项目名称、小区名称 | 多项目时必需 |
| `status` | 整改单状态、整改状态、处理状态 | 必需 |
| `task` | 品质检查任务名称、检查任务、检查批次 | 可选 |
| `problem` | 问题描述、问题内容、不合格项 | 必需 |
| `board` | 所属板块、业务板块、责任板块 | 必需 |
| `dimension` | 检查维度、检查项、检查类别 | 可选 |
| `score` | 扣罚分值、扣分、处罚分值 | 可选，缺失按 0 |
| `measure` | 整改措施、处理措施 | 可选 |
| `implementation` | 实施描述、整改说明 | 可选 |
| `submitter` | 提交人、检查人、创建人 | 可选、敏感 |
| `submitted_at` | 提交时间、创建时间、检查时间 | 可选 |

## 字段识别

扫描每个工作表前 20 行，以必需字段和别名命中数量选择表头。若多个候选分数接近，要求通过 `--sheet` 或 `--header-row` 消除歧义。

## 配置文件

```json
{
  "field_aliases": {
    "problem": ["现场问题"],
    "board": ["专业条线"]
  },
  "done_statuses": ["已整改", "已完成", "已关闭"],
  "pending_statuses": ["待整改", "整改中", "未完成"],
  "no_issue_values": ["无", "无问题", "正常", "符合"]
}
```

配置只保存字段别名和规则，不得复制项目名、人员、工单号或问题明细。
